+PLUS is a self-signing, automatic update engine for GrapheneOS. On your phone it takes each official GrapheneOS update, adds the plus-ups you chose, signs the result with a key only you hold, and installs it. Your phone then trusts your key, not anyone else's.

What +PLUS is

GrapheneOS phones update themselves with images signed by GrapheneOS. Adding anything to the operating system breaks that chain: the phone would no longer accept GrapheneOS's updates, and you would have to rebuild every release on a computer.

+PLUS takes the place of GrapheneOS's own update app and keeps the phone updating by itself:

  1. Every 6 hours it checks GrapheneOS's release server for your phone model.
  2. It downloads the official update and checks GrapheneOS's signature on it.
  3. It unpacks the system images, adds +PLUS and the plus-ups you chose, packs them again, and signs the whole update with your key, all on the phone.
  4. Android's own A/B updater writes it to the inactive half of the phone's storage, so the image you are running is never touched while the new one is prepared.
  5. You restart when it suits you.

It runs on its own on Wi-Fi while the phone charges. On mobile data it shows "Update available" with an Update now button instead. With no plus-ups chosen, or no catalog at all, +PLUS simply keeps GrapheneOS up to date, signed with your key.

The security concept

A GrapheneOS phone with a locked bootloader only starts system images signed with a key it trusts. Normally that is GrapheneOS's key. +PLUS sets it to your key:

  • Your key is created on your side. The setup page creates it in your browser. It is never uploaded, and you keep a backup: printed, in a password manager or encrypted with a hardware token. How you keep it is up to you.
  • The phone's bootloader is locked again with your key. Verified boot then accepts only images signed with it, and checks every system partition as it is read. At startup the phone shows that it runs an operating system signed with a key other than Google's, with your key's fingerprint.
  • On the phone, the key lives in Android's hardware-backed keystore. It can sign only within 30 minutes of unlocking the phone with your PIN, password or fingerprint, so every update waits for you once.
  • Installing and activating are separate. A new image goes to the inactive slot and is not used until you tap Restart to finish on an unlocked phone, after a list of what changed. Restarting, a crash or holding the power button all start the image you already had.

Someone who holds your locked phone therefore can't activate an image, even with a valid key, because they can't unlock the phone.

Your key backup is as powerful as the key itself: whoever has it can sign updates your phone accepts. Keep it offline. Coercion and malware on an already unlocked phone are not prevented by any update system; read the change list before you tap Restart to finish.

Where the checks are

StepWhat is checkedWhat it stops
First setup (in the browser) The GrapheneOS update file you pick is checked against GrapheneOS's published keys for your model. The firmware the page gets from GrapheneOS's server must match, byte for byte, the firmware in that signed file. The phone's model and storage layout must match the build. A modified or wrong GrapheneOS file; firmware from anywhere else; loading onto the wrong phone.
Each update (on the phone) The release must be for your model and channel, and newer than what you run. The update file's signature is checked against GrapheneOS's keys built into +PLUS. Old releases being pushed back onto the phone; images that didn't come from GrapheneOS.
The catalog The catalog link names the catalog's key by its SHA-256. The phone checks that key, the signature, an expiry date (28 days), and that the catalog is not older than the last one it saw. A swapped catalog, a modified list, or an old list replayed to hold back fixes.
Each plus-up Its file hash, package name and version must match the signed catalog. Its signing certificate is remembered the first time and must never change. A modified app, or an app replaced by one from someone else.
Signing Your key signs only within 30 minutes of an unlock. Images signed in the background on a phone nobody unlocked.
Activation Restart to finish, from an unlocked phone, after the list of changes. Someone holding your locked phone starting a new image.
Every start Verified boot with your key checks the boot images and, block by block, the system partitions. Changes made to the phone's storage outside the update path.

If the catalog can't be reached or fails a check, +PLUS still installs GrapheneOS's update and keeps the plus-ups it already has. A catalog problem never holds back a GrapheneOS security update.

How plus-ups are added

A plus-up is an app, or a group of apps, built into the operating system image rather than installed on top. That is what lets it do things a normal app can't, such as answering a phone call.

  1. The catalog is a signed list on this site. It names each plus-up's apps with their version, file hash, signing certificate and the system permissions they need.
  2. You choose plus-ups in the +PLUS store on the phone.
  3. On the next build +PLUS downloads the chosen apps, checks them against the catalog, and puts them into the image (/product/priv-app for apps that need system permissions) together with the permission list Android requires for them. Then it signs the image with your key.
  4. Updates to a plus-up arrive the same way: as a new image. GrapheneOS doesn't let apps replace system apps on their own, so nothing bypasses your key.
  5. Removing a plus-up happens only when you ask for it, because Android deletes a removed system app's data.

Because the phone builds the image itself, plus-ups can be offered for every GrapheneOS release on every supported Pixel without anyone redistributing GrapheneOS.

The first plus-up: call screening

Our first plus-up is call screening, a much-requested feature that the project's author really wanted. It is highly customizable and runs entirely on the phone, with on-device search, transcripts and call notes. It is in the catalog now as a test version: choose Phone+ in the +PLUS store.

Phone+ is GrapheneOS's phone app with a call assistant added:

  • Screening. The assistant answers callers who aren't in your contacts, asks who's calling and why, and shows you the call with a live transcript. You answer, ask a follow-up, put the caller on hold, type a reply that the assistant reads out, ask them to text you, or decline. Robocalls and silent calls end by themselves; a caller who asks for money, codes or passwords is shown with a warning.
  • Messages instead of voicemail. Calls you don't pick up can leave a message with the assistant, transcribed on the phone.
  • Call recording and transcripts of both sides, on the phone, with automatic recording rules and a recording notice.
  • Call notes and search with the optional +PLUS AI plus-up: a summary after each call and questions about past calls, answered by a language model on the phone.
  • Your data stays yours: screening history, transcripts and audio can be exported to one file, deleted, or kept for a period you choose.

Setting up a phone

1. Load the phone

To keep the first setup simple, the whole job of patching a GrapheneOS image with +PLUS, the re-signing and update tool, happens in your browser. It takes much longer than dedicated computer tools, but it is foolproof and automatic, and nothing is sent anywhere. The setup page loads the phone the way GrapheneOS's own installer does, starting from the phone's original Android or from GrapheneOS.

  1. Pick the official GrapheneOS update file for your phone.
  2. Create your key and save its backup. The page shows it as text, a QR code and a printable sheet.
  3. Build the image (20 to 45 minutes), then connect the phone in its bootloader and load it. The page unlocks the bootloader, writes everything, and locks it again with your key.
  4. On the phone, go through GrapheneOS setup and set a PIN. Open +PLUS (Settings > System > System update), tap Import your key and scan the QR code. Then turn OEM unlocking off again.

You can back up your own signing key for special recovery tasks, if you ever need it: a repair image signed with your key installs without unlocking the phone. The key backup converter turns the backup into standard key files for avbroot, OpenSSL and fastboot.

2. Add call screening

  1. In the +PLUS store, choose Phone+. The next update is built with it; tap Restart to finish when it's ready.
  2. Phone+ uses Google's speech engine for listening and speaking. In GrapheneOS, install sandboxed Google Play from the App Store, then install Speech Services by Google from Play (package com.google.android.tts, also listed as Speech Recognition & Synthesis).
  3. Open Phone+ > Settings > Call screening > Setup. The checklist shows what is missing, each with a button that fixes it:
    • Phone+ is your default phone app;
    • a speech recognizer is installed, may use the microphone, and can listen to calls;
    • offline English recognition is downloaded;
    • an English voice is installed for the assistant;
    • call audio works, and the screening script is loaded.
  4. Turn on Screen calls and pick which calls to screen: callers not in your contacts, only private numbers, or only when you tap Screen call.
  5. Optionally add the +PLUS AI plus-up and a model for call notes and search.

The settings

  • Always ring: contacts, starred contacts, numbers you called recently, and a never-screen list.
  • When you don't answer: take messages instead of voicemail, and how long a call rings first (shorter than your carrier's voicemail delay).
  • Voice: the assistant uses the voice chosen in Android's text-to-speech settings.
  • Transcripts and summaries: transcribe recordings, summarize calls with +PLUS AI.
  • Your call data: export everything to one file.
  • Advanced: the screening script and its options, saved replies, speech downloads, recording format and automatic recording, how screened calls show in Recents, how long transcripts and audio are kept, and diagnostics.

Privacy: everything on the phone

Screening, recognition, the assistant's voice, transcripts, call notes and search all run on the phone. Phone+ sends nothing to us or to anyone else.

The speech engine comes from Google. Once it is set up, with offline English and a voice downloaded, we think you can switch off its network access to prevent data leakage: in GrapheneOS, long-press Speech Services by Google > App info > Permissions > turn off Network. Do the same for Phone+ if you like; it doesn't need the internet. Make a test call afterwards to check that screening still works, and switch network access back on for a while when you want to download a new voice or language.

Customizing the screening script

What the assistant says and decides is a screening script: a small JavaScript program that Phone+ runs in a sandbox. The built-in one covers most needs through its options, shown in Settings > Call screening and under Advanced: which calls to screen, your first name, the greeting, how many follow-up questions, how long the phone rings for you, what happens when a caller asks for money or codes, and the message greeting.

To go further, write your own:

  1. Settings > Call screening > Advanced > Script library. Open the default script and choose View source to start from it.
  2. Edit it on a computer. The script syntax page describes the handlers, the actions and the limits.
  3. In the Script library, choose Import script. Phone+ shows its name, version, author, API level and SHA-256, and asks you to confirm with your screen lock.
  4. Choose Run tests to run the script's own test calls, then Activate.

A script can't reach the internet, your files or your contacts. It sees only the call it is screening and the notes it saved itself, and it returns actions that Phone+ checks before running them. If a script keeps failing, Phone+ switches back to the default script and tells you. Reset to default is always there.
