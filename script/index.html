Screening script syntax

Phone+ call screening, script API level 1

+PLUS home Shape of a script Handlers The call Actions Options and prompts Helpers Tests Limits Example

A screening script decides what happens to a call and what the assistant says. Phone+ calls the script's handlers as the call goes on; each handler returns actions, which Phone+ checks and then carries out. The script never touches the call, the microphone or the screen directly.

Scripts are plain JavaScript (ES5 with a few later features, run by Mozilla Rhino). Start from the built-in script: Settings > Call screening > Advanced > Script library > Default screening > View source.

The sandbox: no network, files or contacts; eval and Function are disabled; Date.now() and Math.random() are fixed by Phone+ for each event, so a call can be replayed exactly from its log.

Shape of a script

var meta = { id: "my-screening", name: "My screening", version: "1.0.0", api: 1,
             author: "You", description: "One line about what it does." };
var options = [ /* settings shown in Phone+, see Options */ ];
var prompts = { hello: "Hello? Are you there?" };   // fixed lines, synthesized ahead of time
var tests = [ /* test calls, see Tests */ ];

function on_incoming(ev, call, state, config) { return [screen()]; }
function on_start(ev, call, state, config) { /* ... */ }
// ...more handlers

Every handler gets the same four arguments: ev (this event), call (a snapshot of the call), state (what your script stored last time) and config (the values of your options). It returns either an array of actions, or result(actions, state) to also save new state. State is a plain object, kept for the length of the call.

Handlers

Define only the handlers you need. A missing handler does nothing.

HandlerWhenev fieldsMay return
on_incomingThe phone starts ringing.— Exactly one of screen(), ring(), silence(), reject_incoming() (plus log).
on_startThe assistant has answered. origin: auto, manual (you tapped Screen call) or unanswered (you didn't pick up); ask: "urgent" when you tapped Urgent? for a contact; recovered, disclosed after Phone+ restarted mid-call. Conversation actions.
on_caller_saidThe caller finished a sentence.text Conversation actions.
on_silenceAn ask or listen timed out.— Conversation actions.
on_user_actionYou tapped a chip, or sent a typed reply. id (the chip's or input's id), value (typed text)Conversation actions.
on_user_typingYou started or stopped typing a reply.active Conversation actions.
on_user_unavailableYou didn't answer in time after present or connect.after (present or connect), waited_msConversation actions.
on_timerA timer you set ran out.nameConversation actions.
on_assistant_resultAn on-device language model answered. req_id, ok, text, json, error, timing_msConversation actions.
on_interruptedYou took or placed another call. reason (e.g. outgoing_call) One closing end_call, and records.
on_endThe call is over.reason Records only: summary, tag, remember, store, log.

After an ending action (connect, take_message, end_call) a result may contain only records.

Actions

Actions are plain objects. The standard library builds them for you:

BuilderDoes
The decision (only in on_incoming)
screen()The assistant answers.
ring()Ring as usual.
silence()Let the call through without ringing; you can still answer it.
reject_incoming()Decline the call.
Speaking and listening
say(x)Say a line. x is text, { prompt: "key" }, or { text, disclosure: true } for the line that tells the caller the call is recorded.
ask(x, timeout_ms)Say a line and listen for the answer (default 8 s).
listen(timeout_ms)Listen without speaking.
What you see
present(card, wait_ms)Show you the call and ring; on_user_unavailable follows if you don't answer within wait_ms (default 25 s).
update(card)Change the card while it is shown.
chips([chip(id, label, style, notify)…])Buttons for you; style normal, primary or warning.
prompt_input(id, hint), clear_input()A box to type a reply; it arrives as on_user_action with ev.value.
status(text)A short status line on the screening screen (up to 80 characters).
Endings
connect(wait_ms)Ring you to take the call while the caller waits; say a line first if you want them to hear one.
take_message(x, max_ms, beep)Say x, then record a message.
end_call(reason, closing)Say an optional closing line and hang up.
Records
summary(line, tags)The one-line description in Recents.
tag("robocall", …)Labels on the call (a-z 0-9 _).
remember(fields, opts)What you learned, e.g. { name, org, reason }, with an optional confidence.
store(scope, key, value)Save data for later calls: scope number or global; read back from call.memory.
log(level, msg)A line in the call's diagnostics.
Timers and the assistant
set_timer(name, ms), cancel_timer(name)At most 4 timers, 60 s each.
assistant_generate({ req_id, input, prefix, json_schema, max_tokens, temperature }) Ask the on-device model (when call.capabilities.assistant is set); the answer arrives in on_assistant_result.
assistant_warm(prefix)Prepare the model with a prompt prefix ahead of time.

A card is { title, subtitle, fields: [{ label, value }], caution, alert }: the title (up to 60 characters) is who's calling, up to 8 fields hold what was said, and caution shows a warning.

Phone+ checks every action. A malformed one is dropped and reported in the call's diagnostics; the rest still run.

Options and prompts

options become settings in Phone+. Their values reach every handler as config:

var options = [
  { key: "mode", type: "choice", label: "Which calls to screen", promoted: true, default: "unknown",
    summary: "These calls are answered by the assistant first.",
    choices: [["unknown", "Callers not in your contacts"], ["withheld", "Only private numbers"]] },
  { key: "owner_name", type: "text", label: "Your first name", maxLength: 40, default: "" },
  { key: "wait_s", type: "number", label: "Ring me for", min: 10, max: 45, default: 25 },
  { key: "polite", type: "bool", label: "Thank every caller", default: true, advanced: true }
];

Types are choice, text, number and bool. promoted options appear on the main Call screening settings screen, advanced ones under Advanced.

prompts are fixed lines, up to 32, synthesized once when the script is activated so the caller never waits for them: use them with say({ prompt: "hello" }). Lines with changing text are spoken as they come.

Helpers

FunctionReturns
norm(s)Lower case, punctuation removed, single spaces: what lexicons match against.
words(s)The words of norm(s).
matchAny(lexicon, text)The first phrase or regular expression of the list found in the text, or null.
replyClass(text, { field, yesNo })"repeat" ("Sorry, what?"), "presence" ("Yes, I'm here"), "refusal" ("I'd rather not say") or "answer".
isRepeatRequest, isPresenceReply, isRefusalThe single tests behind replyClass.
clip(s, n)The text cut to n characters with an ellipsis.
fill(template, values)"Hi {name}" with the values filled in.
result(actions, state)A handler's result with new state.
assert(cond, msg)Throws when cond is false (for tests).

Any of these can be replaced by defining a function with the same name in your script.

Tests

tests are simulated calls; Script library > Run tests plays them through your handlers and reports each result:

var tests = [
  { name: "A dentist's office is shown to you",
    caller: ["Hi, this is Maria from Bright Smile Dental.", "I'm calling to reschedule your cleaning."],
    expect: { decision: "present", card: "Bright Smile Dental", caution: false } },
  { name: "Manual mode rings every call", config: { mode: "manual" }, expect: { decision: "ring" } },
  { name: "Hold keeps the caller, then a message is taken",
    caller: ["Hi, this is Maria from Bright Smile Dental."],
    user: { chip: "hold" }, expect: { outcome: "message", bot_says: "Thanks for holding" } }
];

A test can set config, call (e.g. a contact or a withheld number), origin, ask, the caller's lines (null is a silence) and what you do (user: "answer", { chip: "id" } or { typing: true }). expect can check decision, outcome, card, card_lacks, caution, tags, bot_says and max_questions. Up to 64 tests.

A handler that throws, runs too long or returns something unusable counts as a failure. If the active script keeps failing, Phone+ goes back to the default script and tells you.

A complete small script

It screens unknown callers, asks once who's calling, shows you the answer, and takes a message if you don't pick up.

var meta = { id: "small", name: "Small screening", version: "1.0.0", api: 1,
             author: "You", description: "Ask once, show me, else take a message." };
var options = [
  { key: "wait_s", type: "number", label: "Ring me for", min: 10, max: 45, default: 20 }
];
var prompts = {
  greeting: "Hi, this is an automated call assistant, and this call is recorded. Who's calling, and why?",
  message: "They can't come to the phone. Please leave a message after the tone."
};

function on_incoming(ev, call, state, config) {
  return [call.contact ? ring() : screen()];
}

function on_start(ev, call, state, config) {
  if (ev.origin === "unanswered") return [take_message({ prompt: "message" }, 60000)];
  return [ask({ prompt: "greeting", disclosure: true }, 8000), status("Listening")];
}

function on_caller_said(ev, call, state, config) {
  if (replyClass(ev.text) === "repeat") return [ask({ prompt: "greeting" }, 8000)];
  var card = { title: clip(ev.text, 60), fields: [{ label: "Said", value: clip(ev.text, 120) }] };
  return result([present(card, config.wait_s * 1000)], { said: ev.text });
}

function on_silence(ev, call, state, config) {
  return [end_call("silent", "Sorry, I can't hear anyone. Goodbye.")];
}

function on_user_unavailable(ev, call, state, config) {
  return [take_message({ prompt: "message" }, 60000)];
}

function on_end(ev, call, state, config) {
  return [summary(state && state.said ? clip(state.said, 80) : "Screened call")];
}

var tests = [
  { name: "An unknown caller is shown to me", caller: ["It's Sam from the garage, your car is ready."],
    expect: { decision: "present" } }
];
